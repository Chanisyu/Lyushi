# 记录期间修改事项与标签

适用版本：0.7.0 起。Android、Windows 和 Ubuntu 提供一致的活动编辑规则。

## 操作

开始记录后，点击事项右侧的“修改”，调整事项名称或标签，再点击“保存”。可选择已有标签或“无标签”；新增、删除标签仍须先结束记录。

表单打开期间继续计时。取消不保存，保存成功后主页面立即显示新内容；断网时先保存到本机，恢复连接后同步。应用重新打开时恢复已保存的名称、标签和计时状态。

Android 屏幕旋转保留编辑草稿与原始版本信息。明确取消或完全退出后丢弃未保存输入。

## 修改范围

| 当前阶段 | 保存范围 | 保留内容 |
| --- | --- | --- |
| 专注 | 当前逻辑任务的根事项及标签，全部专注区间共同引用 | 所有分心快照、其他任务 |
| 分心 | 当前尚未结束的最后一个分心区间 | 待恢复的原事项及标签、此前分心区间、其他任务 |

例如，“背单词 → 点饭 → 背单词”恢复专注后改为“英语复习”，两个专注区间均显示“英语复习”，中间的“点饭”保持原样。分心期间把“点饭”改为“选择午餐”时，恢复后仍显示原任务名称及标签。

修改名称和标签不改变任务编号、账本、开始或结束时刻、已有分段、当前阶段及有效时长，不新增计时区间。只有实际更改内容并保存时才生成一个新版本及一条待同步操作；与原内容相同的保存不产生额外版本。

事项须为不超过 10,000 个 UTF-16 单元的非空文本。现有标签快照即使已从候选列表删除，仍可原样保留或清空；不能将已由其他设备删除的候选重新赋给任务。历史快照不会自动恢复为可用标签。

## 跨设备变更

表单以打开时的任务编号和版本为保存条件。如果其他设备已经修改、结束任务或切换专注／分心阶段，应用保留草稿并提示核对，停用该表单的保存按钮。用户可复制输入、取消表单，确认主页面状态后重新打开修改。旧表单不能覆盖最新内容、修改下一项任务或重新启动已结束记录。

两台设备离线修改同一版本时，沿用既有冲突规则：完整保留双方版本，重新连接后提示核对。各自未结束的分支可能需要分别结束；不自动合并时间线，也不将两个分支的时长相加。只读冲突档案继续保留原始内容。

网页后台继续只读展示活动任务；原生端保存并同步后，网页可领取最新内容。网页不提供活动编辑或计时控制。

记录期间仍不能切换账本、切换账户、查看明细或进行导入导出。

## 模块职责

| 模块 | 逻辑职责 |
| --- | --- |
| 原生编辑表单 | 单独维护名称与标签草稿，提供保存、取消和状态变化提示；计时刷新不改写草稿 |
| Android 实例状态 | 在同一进程内跨屏幕旋转恢复草稿，并保留打开时的任务编号、版本及标签快照 |
| 本地存储 | 在一个事务内核对活动身份、版本、标签和完整记录；只更正目标元数据，再保存实体与同步操作 |
| 同步与冲突处理 | 沿用完整记录版本、稳定操作编号、重试、分页保护与分支档案 |
| 服务端及网页 | 协议 4 接收原生版本并保留账户隔离，网页继续拒绝活动记录的修改 |
| 备份与 CSV | 按原有格式保留更正后的内容、独立分心快照和冲突档案 |

## 兼容性与验证

同步协议保持 **4**，JSON 备份格式保持 **3**，服务端最低兼容客户端仍为 **0.6.0**。本功能不需要迁移数据库、重置账户、轮换设备密钥或修改服务器配置。0.6.0 客户端可以同步和显示新内容，活动编辑入口由 0.7.0 客户端提供。

领域检查覆盖未分段任务、恢复后的多个专注区间、连续多次分心、空白及超长名称、标签并发删除、无变化保存、失败回滚、过期表单、结束后的保护、重启及备份恢复。桌面真实表单检查覆盖保存、取消和远端变更后的草稿保留；Android 界面检查实际触发屏幕旋转、原版本恢复、过期提示、取消和完整进程退出后的恢复。

本地双客户端联测覆盖活动改名、当前分心更正、恢复专注、并发版本保留及跨端结束。服务端测试验证协议 4 接收、重试去重、完整时间线及网页活动编辑限制。
